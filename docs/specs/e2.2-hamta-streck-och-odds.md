## 6.1 Spelbar (ersätter raden `forslag` och lägger till)

- **Förslaget:**
  - `diff = round2(unibetOdds − riktoddsX)`
  - `forslag = intressant && unibetOdds != null && riktoddsX != null && diff ≥ −tolerans`
  - `tolerans` = `UserSettings.spelbarTolerance`, standard 0,10.
- **Oddsklass** (`oddsClass` i `lib/spelbar.ts`, en ren funktion):

  | Klass | Villkor |
  |---|---|
  | `over` | `diff > 0` |
  | `near` | `−tolerans ≤ diff ≤ 0` |
  | `under` | `diff < −tolerans` |
  | `null` | något värde saknas |

  - Klassen beskriver oddset och gäller även hästar som inte är Intressant. Märket S följer `spelbar`.
  - `override = OFF` med klassen `over` ger grön markering men inget S.
  - `override = ON` med klassen `under` ger S men ingen grön markering.
- **Med toleransen 0,00** blir regeln `unibetOdds ≥ riktoddsX`. Det betyder att ett odds lika med riktoddset räcker, vilket är ett medvetet byte från `>` före E2.2.
- **Grön markering (variant 1 · Ram)** gäller i S3, S4 och S6, i mobil och på desktop.

  | Klass | Oddsfältet | Skillnaden under fältet (desktop: kolumnen Skillnad) |
  |---|---|---|
  | `over` | heldragen kant 2 px `--sig`, bakgrund `--sig-soft`, sken `0 0 10px rgba(70,211,126,.25)` | "+0,31" i mono 11,5 px fet, `--sig` |
  | `near` | streckad kant 2 px `--sig`, ingen bakgrund | "−0,07" i mono och "NÄRA" i Barlow Condensed 10,5 px versaler, båda i `--sig` |
  | `under` | vanlig kant | "−0,15" i `--ink-2` |

  - Tecknen är `+`, `−` (U+2212) och `±` (vid 0), alltid med två decimaler.
  - Skärmläsaren får texten " över riktoddset, spelbart", " under riktoddset, nära, spelbart" eller " under riktoddset".
  - Färgen bär aldrig informationen ensam: skillnaden och ordet "nära" står i text, och S-märket finns. Texten ska ha kontrast 4,5:1 och kanten 3:1.
  - På tavlan (S3) används `--head-up` (#46D37E, finns i `tokens.css`).
- **Riktlinjen 2,00** är oförändrad. Taggen "Under 2,00" påverkar inte förslaget eller färgen.
- **Trollspöt** (beslut 2026-10-21, Claudes förslag): "minst X" = max(2,00, riktodds − tolerans, ≈odds). Toleransen dras alltså av från riktoddsdelen men inte från 2,00, så att Trollspöt och Spelbar säger samma sak.

## 6.9 Hämta streck och odds (nytt, efter 6.8)

- **En knapp, två delar som körs parallellt:**
  - **Strecket:** befintliga `refreshStreck` (`POST /api/rounds/[id]/refresh`), följt av `POST /api/rounds/[id]/riktodds`.
  - **Unibets odds** (10.5).

  Varje del lyckas eller misslyckas för sig. Efteråt läser klienten om omgången (`loadRound`) och räknar fram "nya Spelbara" och listan i "Visa vilka" genom att jämföra före och efter, som `diff` i `StreckRefresh.tsx`.
- **Alla hästar:** oddsen hämtas för alla starter i alla avdelningar. Det blir ett anrop för banan och ett per avdelning, alltså 9 anrop. Inget schemalagt jobb.
- **Överskrivning:** en hämtning skriver över alla odds, även egna. Ett eget odds som ersätts sparas för Ångra (8.3).
  - Ångra gäller den senaste hämtningen, tills nästa hämtning eller tills loppet startar. Efter Ångra är källan eget igen.
  - Ett odds som skrivs in för hand får källan eget och gäller tills nästa hämtning.
- **Bet-oddset ändras aldrig** av en hämtning. Regeln i S6a om att en rättning efter Bet ändrar `betOdds` gäller bara inskrivna odds.
- **Hoppas över:** avdelningar vars lopp har startat, och starter som är strukna hos ATG.
- **Struken hos Unibet** (status ≠ "Starter"):
  - `unibetOdds = null` med källan Unibet
  - taggen "Struken hos Unibet"
  - hästen blir inte Spelbar, utom med `override = ON`.
- **Saknas hos Unibet:** oddset ändras inte, och hästen räknas i "fanns inte hos Unibet".
- **Ingen ögonblicksbild utan odds:** har inget lopp odds (`hasFixedPrices = false` eller `prices = []`) sparas ingen ögonblicksbild, och inga `Mark` ändras. Strecket sparas som vanligt.
- **Spärr:** högst en oddshämtning per omgång och 2 minuter, räknat från `OddsFetch.takenAt`.
  - Servern svarar 429 med `retryAfterSec`.
  - Att göra om en del som misslyckades räknas inte mot spärren.
- **Gamla odds:** äldre än 12 timmar (samma gräns som `STRECK_STALE_MS`). Gränsen gäller varje del för sig, och den äldsta delen styr tavelknappen.
- **Rörelsen** räknas från den första ögonblicksbilden med platsodds för starten i omgången.
- **Avrundning:** `Math.round(x * 100) / 100`, så att 1,1666666667 blir 1,17. Avrundningen görs innan något sparas eller jämförs.

## 8.3 Unibets odds (ny, i 8) – förslag som backend-byggaren får ändra

Mönstret följer `RoundSnapshot`/`StreckValue`: ett huvud per tryck och en rad per start. Det är gemensam data som bara hämtningen skriver.

```prisma
enum OddsSource {
  MANUAL   // inskrivet av användaren
  UNIBET   // hämtat
  @@schema("spelvarde")
}

// En ögonblicksbild = ett tryck på Hämta streck och odds (oddsdelen).
model OddsFetch {
  id          String    @id @default(cuid())
  roundId     String
  round       Round     @relation(fields: [roundId], references: [id], onDelete: Cascade)
  userId      String?
  user        User?     @relation(fields: [userId], references: [id], onDelete: SetNull)
  takenAt     DateTime  @default(now())
  finishedAt  DateTime?
  legsOk      Int[]
  legsFailed  Int[]
  legsSkipped Int[]     // lopp som hade startat
  prices      UnibetPrice[]
  @@index([roundId, takenAt])
  @@schema("spelvarde")
}

model UnibetPrice {
  id        String    @id @default(cuid())
  fetchId   String
  fetch     OddsFetch @relation(fields: [fetchId], references: [id], onDelete: Cascade)
  startId   String
  start     Start     @relation(fields: [startId], references: [id], onDelete: Cascade)
  placeOdds Decimal?  @db.Decimal(6, 2)   // FixedPlace, avrundat
  winOdds   Decimal?  @db.Decimal(7, 2)   // FixedWin, avrundat (kan vara över 99,99)
  status    String                        // Unibets competitor.status, t.ex. "Starter"
  @@unique([fetchId, startId])
  @@index([startId])
  @@schema("spelvarde")
}
```

**Ändringar i befintliga modeller**
- `Mark`:
  - `unibetOddsSource OddsSource?`, som är null när oddset saknas
  - `replacedOdds Decimal? @db.Decimal(6,2)` och `replacedByFetchId String?` för Ångra.
- `UserSettings`: `spelbarTolerance Decimal @default(0.10) @db.Decimal(4,2)`, med en check på 0,00–0,50 i migreringen.
- Valfritt: `Race.unibetEventKey String?` som cache.

**Hur hämtningen fyller `Mark`**
- Hämtningen skriver odds till `Mark` för alla starter, så att befintlig kod (`forslag`, `PlatsPanel` och `Outcome`-frysningen) fortsätter att läsa `Mark.unibetOdds`.
- Per avdelning körs en transaktion med `upsert` på `(userId, startId)` för alla starter som inte är strukna hos ATG. Den sätter:
  - `unibetOdds` (null om hästen är struken hos Unibet)
  - `unibetOddsSource = UNIBET`
  - `unibetOddsAt = takenAt`

  och nollställer `unibetOddsPrev`.
- Saknas en `Mark` skapas den med `interesting = false`. `Outcome` fryses bara för I, S och B, så de nya raderna påverkar inte statistiken.
- Raderna skrivs för användaren som tryckte. Det räcker eftersom appen bara har en användare i dag (beslut 2026-10-21, Claudes förslag).
- Alternativet är att räkna fram oddset vid läsning. Byggaren väljer, men befintliga läsare måste fortsätta fungera.

**Ångra**
- När oddsdelen startar nollställs `replacedOdds` och `replacedByFetchId` på användarens alla `Mark` i omgången.
- Om en `Mark` hade källan `MANUAL` med ett annat värde, sparas det gamla värdet i `replacedOdds` och `replacedByFetchId` sätts till den nya `OddsFetch.id`.
- Ångra sätter `unibetOdds = replacedOdds` och `unibetOddsSource = MANUAL`, och nollställer sedan båda fälten.

**Källan eget:** `PUT /api/marks/[startId]` med `unibetOdds` sätter `unibetOddsSource = MANUAL`, och `unibetOddsPrev` som i dag.

**Migreringen E2.2** lägger till de nya tabellerna och fälten.
- Befintliga `Mark` med `unibetOdds` får `unibetOddsSource = MANUAL`.
- `spelbarTolerance` får standardvärdet 0,10.
- Tidigare frysta `Outcome` räknas inte om.
- Migreringen ska vara additiv. Den körs mot drift (Tabellgissningens Supabase, schemat `spelvarde`) **först efter Mikaels ja**, via `bash scripts/prod-db.sh deploy`.

## 10.5 Unibets racing-API (ny, i 10) – verifierat 2026-10-21

- **Anrop:** `POST https://rsa.unibet.co.uk/api/v1/graphql` med JSON `{query, variables}`, utan inloggning.
  - Headrar: `origin: https://www.unibet.se` och `content-type: application/json`.
  - Det är samma API som unibet.se:s travsida använder. Det är inofficiellt och introspektionen är avstängd.
  - All tolkning ligger i `lib/unibet.ts`, med egna typvakter som i `lib/atg.ts`. Okända fält ger `null` och en loggad varning, aldrig en krasch.
  - Tester körs mot sparade svar i `test/fixtures/unibet/`: en bana, ett lopp med odds och ett lopp före öppning.
- **Anropen görs bara på servern**, med en timeout på 8 s per anrop.
- **Banor och lopp** (1 anrop):
  ```graphql
  query { viewer { meetings(raceTypes:["H"], countryCodes:[], clientCountryCode:"SE",
    startDateTime:"<ISO>", endDateTime:"<ISO>") {
      meetingKey name events { eventKey sequence eventDateTimeUtc status } } } }
  ```
  - Tidsfönstret är omgångens datum 00:00–23:59 i Europe/Stockholm, uttryckt i UTC.
  - `countryCodes:["SE"]` ger ett tomt svar. Filtrera i stället på att `meetingKey` innehåller `.H.SWE.<bana>`, t.ex. `202610241300.H.SWE.jagersro.5`.
  - `<bana>` är `Round.trackName` normaliserat: gemener, å och ä blir a, ö blir o, och blanksteg och bindestreck tas bort.
  - `events[].sequence` är loppnumret på banan, alltså `Race.raceNumber`. V85-1 på Jägersro är lopp 5.
  - Hittas ingen bana blir läget "Unibet har inga odds än".
- **Odds per avdelning** (1 anrop per avdelning):
  ```graphql
  query { viewer { event(eventKey:"…", clientCountryCode:"SE") {
    hasFixedPrices markets { name priceTypes { code name status } }
    competitors { name sequence status prices { betType code price flucs { price timestampUtc } } } } } }
  ```
  - `competitors[].sequence` är startnumret och paras med `Start.number`. Namnet används bara som kontroll och i loggen.
  - `betType "FixedPlace"` är platsoddset och `"FixedWin"` vinnaroddset. `price` är oavrundat. `flucs` används inte.
  - `status "Starter"` betyder att hästen startar. Andra värden betyder att den är struken hos Unibet.
  - Före öppning är `hasFixedPrices = false` och `prices = []`, trots att marknaden står som Open.
- **Region:** det är okänt om Unibet svarar på anrop från Vercel i USA. Byggaren provar från en förhandsdeploy. Fungerar det inte används `export const preferredRegion = "arn1"` i rutterna.
- **Loggning:** `FetchLog` med `UNIBET_MEETINGS` och `UNIBET_LEG_n`.
- **Strecket:** hämtas som förut, med `refreshStreck` och sedan riktoddset.

## 12. API-rutter (nya)

| Rutt | Beskrivning |
|---|---|
| `POST /api/rounds/[id]/unibet` | Kontrollerar spärren. Inom spärren svarar den 429 med `{error:"Nyss hämtat. Försök igen om 1 min 42 s.", retryAfterSec}`. Annars skapar den `OddsFetch`, slår upp banan och loppen och svarar `{fetchId, legs:[{leg, eventKey\|null, skipped:"started"\|"no-event"\|null}]}`. Hittas ingen bana svarar den `{fetchId:null, noMeeting:true}`, och inget sparas. |
| `POST /api/rounds/[id]/unibet/[fetchId]/legs/[leg]` | Hämtar en avdelning och skriver `UnibetPrice` och `Mark`. Svarar `{leg, ok, noPrices, withOdds, missing:[nr], scratchedAtUnibet:[nr], replaced:[{startId, from, to}]}`. Går att köra om och räknas då inte mot spärren. |
| `POST /api/rounds/[id]/unibet/[fetchId]/finish` | Saknar hämtningen priser tas `OddsFetch` bort och svaret är `{saved:false}`. Annars sätts `finishedAt`, `legsOk`, `legsFailed` och `legsSkipped`. |
| `POST /api/rounds/[id]/unibet/[fetchId]/undo` | Tar emot `{startId?}` och återställer ersatta egna odds. Svarar 409 med "Ångra gäller bara den senaste hämtningen." om en nyare hämtning finns, och 409 efter loppets start. |

Klienten kör oddsdelen som en kedja: först `unibet`, sedan högst 4 avdelningar samtidigt (lamporna tänds efter hand) och sist `finish`. Strecket körs parallellt. Alla rutter har `maxDuration = 60`.
